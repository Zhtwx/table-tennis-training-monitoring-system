# 运动员所属教练数据设计

## 目标

为每个运动员建立唯一、持久的所属教练关系，教练与运动员的归属不再由训练计划推断。

## 数据模型

`athlete.primary_coach_id` 是可空的 `INT` 外键，引用 `coach.id`。`NULL` 表示暂未分配所属教练；删除被分配的教练须被拒绝，避免产生无意的归属丢失。

训练计划的 `training_plan.coach_id` 保留为该计划的执行教练，不承担运动员档案归属语义。

## 一致性规则

- 新建或修改运动员时，所属教练必须存在于 `COACHES`。
- 存储在运动员数据中的 `coach_name` 仅为展示缓存，必须由 `coach_id` 查得，不能信任客户端传值。
- 所有内存示例运动员都必须具有有效的 `coach_id` 及与之匹配的 `coach_name`。
- SQL 初始化脚本须包含字段、索引、外键及样例数据回填。

## 本轮范围

本轮只实现数据和校验。教练页队员列表改为按该关系查询、运动员详情的教练链接将在下一轮处理。
